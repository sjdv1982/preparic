# W1 shared-state browser acceptance (extra cycle)

Run these checks with Chrome DevTools MCP against one preparic service and a disposable copy of `deployment-mounts/`. Record the initial mount snapshot, service command, browser URLs, and the final mount snapshot. Use the same project in both tabs; a fresh browser context is a different tab, not a different backend project. Do not infer a pass from the pure-state Vitest tests or from HTTP 200 alone. During backend restart, reload every open tab immediately (O6); an unreloaded tab is outside the contract. Wait for each acknowledged edit before the next action unless the scenario explicitly calls for a delayed write.

The checkout's `vite.config.ts` hardcodes the `/preparic` and `/seamless-client.js` proxy target to port 5813. If the disposable backend uses a unique share port, change both proxy targets in the disposable copy to that port and record the diff. Verify browser requests reach that backend (for example, inspect the returned `server` and `X-Seamless-Marker` headers). Never point the disposable Vite app at a shared/default service.

## A. Cold restoration at every reached stage (OC P2/P3/P9; ST 8)

1. Starting at stage 1, reach each available stage in order, retaining its mounted decisions and CIF. At each stage, stop the backend, start it with the same mounts, and reload the browser immediately. Repeat from the restored stage before proceeding to the next stage. Record the mounted marker values, the footer stage, the rendered panel, and the viewer's structure identity for each restart.
2. The footer and panel must show the same derived stage before computed results return. The page must begin with a read-only connecting overlay until all required decision shares have been read. Computed shares may be absent or pending without lowering the stage. No absent result may reset a decision.
3. At stages 1–3, the viewer must show the persisted structure for the current code/assembly. At stages 4–6, it must show fresh S23 all-atom range PDBs or the preparing message while S23 is missing/stale. It must never show an old CIF or range PDB under a restored stage.
4. From stage 3 onward, verify the fit and downstream computations start again after restart. Gates that need fresh results remain closed until the results match current decisions; stage 4 stays editable while its fit is pending. Compare result echoes or execution logs across the restart. Do not count mounted old computed JSON as a fresh result.
5. Reproduce the reported failure by restoring persisted stage 3 and loading both `/` and `/?pdb=1B7F&continue=1`. The stage-3 footer must accompany the stage-3 stackings panel, not the stage-1 structure panel; there must be no persistent discarded-CIF synchronization error. The URL must not reset the existing project or change its stage.

## B. Two tabs, no racing edits (OC P3/P9; ST 7.2)

1. With tabs A and B live at the same stage, press Continue in A while B is idle. B must advance to the same stage without a click or reload. Repeat for each reachable transition, including 1→2 and 3→4. Compare both tabs' current marker/basis with the mounted file; no gate may be skipped when edits do not race.
2. Make a completed upstream edit in A while B is idle at a later stage. Both tabs must lower to the same valid prefix without writing repairs from an observer. The later marker may remain mounted as an orphan but must not display its old stage. Restore the exact prior upstream value and check applicable decisions are retained according to their basis/active flag.
3. Back in A must deactivate the current marker and move idle B back. A later Continue may restore an applicable retained decision. Test a remote assembly/code change while B has a pending structure load: B's stale load must not replace its current visible structure.
4. Specifically at stage 4, press Back in A while B is idle. The mounted `threshold_edits` marker must become `active: false` while retaining its rows and basis. Both tabs must derive stage 3 and render the stackings panel; neither may retain a stage-4 footer or panel from a local-only stage assignment. Press Continue in B and verify the applicable threshold decision is reactivated and both tabs return to stage 4. This is a shared-marker transition, so changing only A's local panel is a failure.

## C. Disconnect, reread, and deferred writes (OC P9; ST 4.1, 7.2a, 8)

1. Establish a populated stage and a visible structure in B. Break only B's shared-state websocket while keeping its page open. Its read-only disconnect overlay must retain the last panel and viewer frame. No pending local build may swap in a new structure while disconnected; controls must be disabled.
2. While B is disconnected, change an upstream decision in A. Reconnect B. B must reread all decision and computed shares, adopt A's accepted values, derive the same stage, and display only a structure matching those values. A previously held computed share with a matching old echo must not be trusted until reread.
3. Start a debounced edit in B, disconnect before its timer fires, change that decision or stage in A, and reconnect B. The deferred write must be dropped under the stage/revision rule. Verify the mounted value stays A's and B reports/adopts it. Repeat with an already handed-off or ambiguous HTTP write: after reread, B must queue a corrective write of the accepted current state even if withdrawal fails. Confirm eventual mounted state and both tabs agree, without assuming cancellation succeeded.
4. Exercise the PDB-specific deferred-intent case without editing while disconnected: while B is live at stage 1, start entering `2JDQ` and disconnect B before the deferred download/commit finishes. A advances the mounted `1B7F` project to stage 2. Reconnect B and let it reread. Its deferred `2JDQ` write must be dropped. Assert that the mounted `pdbcode.txt`, B's shared code state, B's hidden stage-1 `#pdb-code` input value, the displayed viewer title/structure identity, and B's rendered stage all reconcile to the accepted `1B7F` project. A hidden input or viewer title left at `2JDQ` fails even if B follows A to stage 2. Return B to stage 1 and verify the visible field still says `1B7F`; reload B and verify the same state without a new write. Do not type into disabled controls after disconnect.
5. Issue an equal-value write and confirm Continue/Back does not wait indefinitely for a websocket `update`: HTTP acknowledgment or reread of the installed value must complete the action.

## Evidence and scope

For each case record a Chrome DevTools trace or screenshots, websocket/share HTTP events, mounted marker values, and relevant backend logs. The Continue guarantee covers idle follower tabs; simultaneous Continue/Back/edit races are not acceptance cases (D17/O7). A browser kept open through backend restart is also outside acceptance (O6). If W4–W9 are not delivered, mark their stages unavailable rather than passing them. Earlier browser runs that used a disposable share port while Vite still proxied to 5813 are not isolated evidence; see the A4 correction and ledger in `W1_CONTRACT_ACCEPTANCE_MATRIX.md`.
